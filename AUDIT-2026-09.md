# silentgreen: deep audit, September 2026

Written to answer one question the owner asked directly: what is actually built, what is
missing, and where does it sit against the products already in this market. It is meant to
be uncomfortable where that is the honest reading.

The short version: the engine is a real, working, tested tier-0 verifier with a defensible
design. It is roughly one third of the plan. The two things that make it a business rather
than a script, the contract layer and any real-data precision number, do not exist yet.

## 2. The market, and where silentgreen sits in it

### The two camps

**Eval frameworks** (Ragas, DeepEval, promptfoo, Braintrust, Arize Phoenix, OpenLayer).
These score a pipeline against a rubric or a reference set. Every one of them that measures
"faithfulness" or "hallucination" does it by **asking a language model**. Ragas
Faithfulness, DeepEval's hallucination metric, promptfoo's `llm-rubric`, Braintrust's
autoevals: all LLM-as-judge. Independent 2026 benchmarking (Cleanlab, Towards Data Science)
found the default Ragas Faithfulness metric **failed to return any score for 83.5% of
examples** on some datasets, and that the strongest hallucination detector overall was a
paid model-uncertainty product (Cleanlab TLM), still probabilistic.

**Guardrails** (Guardrails AI, NeMo Guardrails, Lakera, LLM Guard, Galileo Protect).
Inline validators that block a response before it ships. Their factuality validators are
again either regex-thin or a secondary model call. They are built for latency-bound inline
use, not for an evidence record you hand an auditor.

**The judge-free corner.** This is small and new. The `GroundEval` paper (2026) argues
exactly silentgreen's thesis: turn verification into a deterministic test of what the agent
retrieved, cited, and was allowed to see; in their case study two frontier judges scored a
response 0.85+ while the agent had never retrieved the artifact its answer depended on.
Azure AI Content Safety ships a "groundedness detection" API but it is a hosted model and
Microsoft-only. Openlayer has deterministic groundedness tests but positions them inside a
broader eval platform.

### Where silentgreen is genuinely differentiated

1. **No model decides a verdict.** Not "a smaller model", not "a calibrated model". A
   deterministic text or numeric comparison. Almost nobody else can say this sentence
   without an asterisk.
2. **`unproven` as a first-class result.** Every competitor collapses "cannot tell" into a
   score or a pass. This is the single hardest thing for an observability vendor to ship,
   because their product is a green dashboard.
3. **The evidence record.** Hash-chained, literal evidence, built to be forwarded to a
   client or an auditor. The eval frameworks produce a score history; they do not produce
   a document.
4. **The basis tag and the confirmation gate.** No competitor distinguishes "matches what a
   human asked for" from "matches what the system used to do", and none refuses a shrug
   before trusting a learned baseline.

### Where the competition is ahead, and it is not close

1. **Real precision/recall numbers.** Ragas, DeepEval, TruLens, Cleanlab all publish
   benchmark numbers on public datasets (RAGTruth, HaluEval, HalluRAG). silentgreen has
   1.00/1.00 on a corpus its own author wrote. That number is worth very little and the
   plan admits it.
2. **Integrations.** promptfoo has dozens of providers and native CI. Braintrust and Arize
   have full tracing UIs. silentgreen has two trace adapters and a file reader.
3. **Claim-level checking.** Ragas and RAGChecker decompose an answer into claims and check
   each. silentgreen checks atoms, not claims, so "the balance is £571, due 2026-09-13"
   passes even if £571 belongs to one invoice and 2026-09-13 to another.
4. **Distribution.** These are funded teams with docs sites, benchmarks, and conference
   talks. silentgreen has a landing page and a `LAUNCH.md`.

## 3. The gap list, ranked by leverage

### A. Ships value now, needs no infrastructure, not built

1. **Tier-1 batch checks: distribution drift and outliers.** Refusal rate, deferral rate,
   answer length, atom density moving sharply against the rest of the batch. Pure
   deterministic, no source needed. The plan has it; the code has only duplication.
2. **An SDK recorder.** `import { recorder } from 'silentgreen/record'`: wrap an agent or
   chain call, capture input, sources, output, actions, write JSONL or POST a batch. The
   plan lists this as a core ingestion path. It is the lowest-friction way a developer
   adopts the tool and it does not exist.
3. **OpenTelemetry GenAI span adapter.** The OTel GenAI semantic conventions are now the
   common shape that OpenLLMetry, Traceloop, Arize, and others emit. One adapter for that
   span shape covers many tools at once. Currently only LangSmith and Langfuse are read.
4. **`--json` output for `check` and `eval`.** Everything is human-text today. The GitHub
   Action greps ANSI-stripped stdout. A machine-readable mode makes the tool scriptable and
   the Action robust.
5. **Extraction hardening, round 2.** Organisation-suffix fuzzing (Ltd / Limited / Inc /
   GmbH / Pvt Ltd), near-miss number detection surfaced as its own note ("£593.00 is close
   to £539.00 in the source, transposition likely"), and a guarded European-decimal reading
   where the source establishes the convention.
6. **Claim-association check (Layer 3, conservative slice).** When the answer says "X of Y"
   or "X due Y" and both atoms exist in the source but are each tied to a different
   identifier or are far apart, report it as `unproven`, never as a fabrication. This is
   the RAGChecker-style catch without the model.
7. **Publish precision and recall in the README** on the expanded corpus, with the
   adversarial breakdown. The plan says the honesty is the marketing; act on it.

### B. The contract layer (Tier 2). The actual moat. Not started.

8. **The contract DSL**: parser, loader, validator. Small YAML. `basis` and `attests`
   mandatory.
9. **The four contract check families**: required fields, value predicates
   (`total > 0`, `currency == source.currency`), required actions (the email was
   *sent*, not just described), forbidden behaviour (never promises a refund).
10. **First-draft contract inference** from a batch, for the user to edit.

Without this, silentgreen is a good linter. With it, it is a thing an agency writes into a
client contract and runs on every delivery.

### C. Hosted depth. Needs the infra the owner is provisioning.

11. Task-inspector endpoint (`GET /v1/batches/:id/tasks/:taskId`) and the side-by-side
    per-atom page.
12. Review-queue UI with server-side attestation validation.
13. Async ingestion (the engine currently runs inside the request).
14. Ledger-verification endpoint (`GET /v1/projects/:id/ledger/verify`).
15. Alert dispatch (Slack / webhook) from a hosted violation.
16. Crypto-shredding: per-evidence encryption key, deletable, chain intact. Must be in the
    first hosted schema, not retrofitted (plan 15.2).

### D. Unresolved design questions that change the architecture

17. **Synchronous gate vs asynchronous monitoring** (plan 15.1). The inline gate that
    blocks a fabricated answer before the customer sees it is the higher-value agency mode
    and needs a different ingestion surface. Decide before the hosted API sets in concrete.
18. **Observation-baseline computation** (plan 15.4). Tier 4 leans on learned baselines
    described in one line. Window length, seasonality, minimum history, drift thresholds,
    retirement on system change: a subsystem with no design.
19. **The real-data gate** (plan Phase 0). Every number is synthetic until 3 real batches
    from people who are not the author replace the fixtures. This is a go-to-market
    dependency, not a coding task, and it blocks the honesty claim the whole product rests
    on.

## 4. Recommended sequence

**This session (engine depth, no infra):** items 1 through 7, then 8 through 10. All of it
is pure functions, testable against the corpus, and shippable to the OSS package the moment
it is written. This roughly doubles what the engine can catch and finally gives it a real
contract story.

**When the infra lands:** items 11 through 16, in that order.

**Owner decisions needed:** items 17 (gate vs monitor), 19 (find 3 design partners). These
are not blocked on code and they are the two things that decide whether Phase 2 onward is
real.
